# Eco-System

Persönliche NixOS-Konfiguration — deklarativ, modular, leichtgewichtig.

Ein System, das auf langfristige Wartbarkeit, reproduzierbare Builds und
Ressourceneffizienz ausgelegt ist. Nicht als Spielwiese, sondern als
tragfähige Basis für zukünftige Features.

---

## Kurzbeschreibung

Eco-System ist eine NixOS-Konfiguration mit folgenden Merkmalen:

- **Flakes-basiert** — reproduzierbare Builds über `flake.lock`
- **Modular** — klare Trennung in `system/`, `userland/`, `hosts/`
- **Host-spezifisch erweiterbar** — gemeinsame Basis plus
  Host-Overrides über Prioritäts-Hierarchie
- **Deploybar über rsync** — Repo nach `/etc/nixos`, dann
  `nixos-rebuild switch --flake /etc/nixos`
- **Leichtgewichtig** — bewusst schlank, um Raum für zukünftige
  Features zu lassen
- **Eigenes Update-Tool** — `eco-update` mit Cache-Check und Retry
- **Eigene GC-Werkzeuge** — `eco-gc-retention`, `eco-gc-collect`
- **Kernel-Auswahl per Import** — LTS, CachyOS v1, v3 Custom

---

## Schnellstart

```bash
# Ins Repo wechseln
eco

# Repo in Kate öffnen
eco-edit

# Änderungen testen
deploy-dry

# Scharf schalten
deploy

# System-Update
sudo eco-update

# Generationen aufräumen (nach Update automatisch)
sudo eco-gc-retention

# Store aufräumen (bei Platzmangel)
sudo eco-gc-collect
```

## Profile-Konzept (implementiert)

Die Module sind der passive Baukasten. Was aktiv ist, entscheiden
Profile:

    profile/base         → Distro-Fundament (mkOverride 1200 für Skalare)
    profile/luis-eco     → Nutzer-Wunsch (mkDefault)
    profile/<sub>        → Sub-Profil (akku, mesh, …) — geplant
    hosts/<host>         → Konkrete Maschine

Die Prioritäts-Hierarchie reicht von `mkForce` (50) bis Option-Default
(1500). Details in `docs/ARCHITECTURE.md`.

`mkForce` wird sparsam eingesetzt — nie auf Listen, die NixOS intern
erweitert (`boot.initrd.*`, `boot.kernelModules`), sonst fehlen
sicherheitskritische Module (LUKS) in der initrd.

- Modularer Aufbau mit `system/` + `userland/` + `hosts/`
